# 2048 게임 명세 (spec)

## 1. 개요

방향키나 스와이프로 4×4 보드의 숫자 타일을 밀어 같은 숫자끼리 합치는 퍼즐 게임이다. 현재 점수와 최고 점수를 보여 주는 점수판이 있다. `apps/2048/` 폴더 안에서 순수 HTML·CSS·Vanilla JS(ES 모듈)만으로 동작하며 외부 라이브러리를 쓰지 않는다. 블로그 테마(라이트/다크)를 따르고, 블로그 글에 iframe으로 넣어도 동작해야 한다.

## 2. 기능 목록

### 2.1 핵심 규칙
- 보드는 4×4(16칸)이다. 상태는 `number[][]`(빈칸 `0`) 또는 타일 객체 배열로 관리한다.
- **새 게임 시작:** 빈칸 중 무작위 2곳에 타일을 하나씩 놓는다.
- **타일 생성:** 유효한 이동(보드에 변화가 생긴 경우)마다 빈칸 하나를 무작위로 골라 타일 1개를 만든다. 값은 **90% 확률로 2, 10% 확률로 4**이다.
- **이동:** 선택한 방향으로 모든 타일이 빈칸 없이 끝까지 밀린다.
- **병합:**
  - 이동 방향의 앞쪽(벽에 가까운 쪽)부터 처리한다. 예: 왼쪽 이동이면 각 행을 왼쪽에서 오른쪽으로 훑는다.
  - 같은 값의 타일 두 개가 만나면 값이 두 배인 타일 하나가 된다.
  - **한 번 이동할 때 타일 하나는 한 번만 병합된다.** 병합으로 생긴 타일은 같은 이동에서 다시 합쳐지지 않는다.
  - 검증 예(왼쪽 이동): `[2,2,2,2]→[4,4,0,0]`, `[2,2,4,0]→[4,4,0,0]`, `[4,4,8,0]→[8,8,0,0]`, `[2,0,2,4]→[4,4,0,0]`, `[2,2,2,0]→[4,2,0,0]`.
- **무효 이동:** 아무 타일도 움직이거나 합쳐지지 않으면 상태, 점수, 타일 생성 모두 변하지 않는다.

### 2.2 점수판
- **현재 점수:** 병합으로 생긴 타일 값의 합만큼 늘어난다. 예: 4+4→8이면 +8.
- 점수가 오르면 `+8`처럼 증가분이 잠깐 떠올랐다 사라지는 표시를 보여 준다. 시각 효과일 뿐이며 스크린리더에는 따로 알리지 않는다.
- **최고 점수:** `localStorage` 키 `2048-best`에 저장한다. 현재 점수가 최고 점수를 넘으면 바로 갱신하고 저장한다. 읽기와 쓰기는 모두 `try/catch`로 감싸고, 저장소를 쓸 수 없으면 메모리 값으로만 동작한다.
- (선택) 진행 중인 게임 상태(보드, 점수, 승리 여부)를 `localStorage` 키 `2048-state`에 저장해 새로고침 후 이어 하기를 지원한다. 저장 데이터가 깨졌으면 무시하고 새 게임으로 시작한다.

### 2.3 새 게임 버튼
- 헤더의 "새 게임" 버튼을 누르면 보드와 현재 점수를 초기화한다. 최고 점수는 유지한다.
- 진행 중인 게임을 확인 없이 재시작한다. 확인 대화상자는 만들지 않는다.

### 2.4 승리와 게임 오버
- **승리:** 처음으로 2048 타일이 만들어지면 보드 위에 오버레이를 띄운다.
  - 문구: "2048 달성! 🎉"
  - 버튼: [계속하기]와 [새 게임]
  - [계속하기]를 누르면 오버레이를 닫고 계속 진행한다. 이후 2048을 다시 만들어도 오버레이를 띄우지 않는다(`won` 플래그 사용).
- **게임 오버:** 빈칸이 없고 상하좌우로 인접한 같은 값도 없으면 오버레이를 띄운다.
  - 문구: "게임 오버" + 최종 점수
  - 버튼: [다시 하기]
- 오버레이가 열리면 첫 번째 버튼으로 포커스를 옮긴다. 오버레이가 열려 있는 동안 방향 입력은 무시한다.

### 2.5 애니메이션
- **이동:** 타일은 절대 위치로 배치하고 `transform: translate()` 전환으로 약 100ms 동안 미끄러지게 한다. 타일마다 고유 `id`를 두어 DOM 요소를 재사용한다.
- **생성:** 새 타일은 scale 0→1로 약 150ms 동안 나타난다(`tile-new`).
- **병합:** 이동이 끝나면 합쳐진 타일이 scale 1→1.15→1로 약 150ms 동안 튄다(`tile-merged`). 합쳐지는 두 타일은 같은 칸으로 이동한 뒤 하나만 남긴다.
- 애니메이션이 진행되는 중에 입력이 들어오면 즉시 최종 상태로 확정한 뒤 다음 이동을 처리한다. 입력은 버리지 않는다.
- `prefers-reduced-motion: reduce`이면 모든 전환과 애니메이션을 끈다.

## 3. 조작

| 입력 | 동작 |
|---|---|
| `ArrowUp/Down/Left/Right` | 해당 방향으로 이동 |
| `W/A/S/D` (대소문자 무관) | 위/왼쪽/아래/오른쪽으로 이동 |
| 스와이프 | 터치를 시작한 점에서 끝난 점까지의 벡터로 방향 결정 |
| `N` | 새 게임 (선택) |

- **키보드:**
  - `document`에서 `keydown`을 받는다.
  - 수정 키(Ctrl/Alt/Meta)가 눌렸거나, 포커스가 버튼·입력 요소에 있으면 무시한다. 버튼에서 Enter/Space가 정상 동작해야 한다.
  - 게임 키를 처리했을 때만 `preventDefault()`를 호출한다.
- **스와이프:**
  - `pointerdown`/`pointerup`(`pointerType === 'touch'` 또는 `'pen'`)을 쓰거나, `touchstart`/`touchend`를 쓴다.
  - 이동 거리가 30px 이상일 때만 인식하고, |dx|와 |dy| 중 큰 쪽의 축으로 방향을 정한다.
- **스크롤 방지 범위:**
  - 보드 요소(`.board`)에만 `touch-action: none`을 적용한다. 보드 위 스와이프가 페이지 스크롤이나 당겨서 새로고침을 일으키지 않게 한다.
  - 보드 밖에서는 일반 스크롤을 허용한다.
  - 방향키의 기본 스크롤은 게임 키를 처리한 경우에만 막는다.
- **iframe 대응:**
  - iframe 안에서는 키 입력을 받으려면 iframe에 포커스가 있어야 한다.
  - 보드를 `tabindex="0"`으로 만들고, 보드를 클릭하거나 탭하면 보드에 포커스를 준다.
  - 보드 아래에 "보드를 클릭한 뒤 방향키로 조작하세요" 안내를 둔다.

## 4. 파일 구조

```
apps/2048/
├── index.html      # 진입점. <head>에 인라인 테마 스크립트, 점수판·보드·오버레이 마크업
├── style.css       # 테마 변수, 레이아웃, 타일 색상, 애니메이션
├── js/
│   ├── game.js     # 순수 게임 로직 (DOM 없음): 상태 생성, move(dir), 타일 생성, 승리·오버 판정
│   ├── render.js   # 상태 → DOM 렌더링, 애니메이션 클래스, 점수·aria-live 갱신, 오버레이 표시
│   ├── input.js    # 키보드·스와이프 입력을 방향('up'|'down'|'left'|'right')으로 변환해 콜백 호출
│   ├── storage.js  # localStorage 래퍼 (try/catch): 최고 점수, (선택) 게임 상태
│   └── main.js     # 모듈 연결, 이벤트 바인딩, 테마 동기화
├── spec.md         # 이 문서
└── tasks/          # 작업 지침
```

- `game.js`는 부작용이 없도록 만든다. `move(state, dir, rng = Math.random)`처럼 난수 함수를 주입받는 순수 함수로 작성해 테스트할 수 있게 한다.
- `move`는 다음을 반환한다.
  - `{ state, moved, scoreGained, merges, spawned }`
  - 렌더러가 애니메이션에 쓰도록 각 타일의 `id`, `from`, `to`, `mergedFrom` 정보를 넘긴다.
- 모든 스크립트는 `<script type="module" src="js/main.js">` 하나로 불러온다. 전역 변수는 만들지 않는다.
- 블로그의 `index.html`, `css/`, `js/`, `posts/`를 참조하거나 수정하지 않는다. 테마 변수는 블로그 값을 복사해 `style.css`에 다시 정의한다.

```
┌─────────────────────────────────────┐
│ 2048                ┌────┐ ┌────┐   │  <header>: h1 + 점수 상자 2개
│                     │점수│ │최고│   │
│                     │ 128│ │2048│   │
│                     └────┘ └────┘   │
│ 같은 숫자를 합쳐 2048을 만드세요.     │  설명 (muted)
│                        [ 새 게임 ]  │  버튼 (최소 44px 높이)
│ ┌─────────────────────────────────┐ │
│ │ ┌──┐ ┌──┐ ┌──┐ ┌──┐             │ │  <main> 안 .board (정사각형)
│ │ │ 2│ │  │ │  │ │ 4│             │ │   - 배경 격자 16칸 + 타일 레이어
│ │ └──┘ └──┘ └──┘ └──┘   ...       │ │   - 오버레이(승리/오버)는 보드 위
│ └─────────────────────────────────┘ │
│ 방향키·WASD 또는 스와이프로 조작      │  도움말 (muted, 작은 글씨)
└─────────────────────────────────────┘
```

- **시맨틱 태그와 접근성:**
  - `<header>`, `<main>`, `<section aria-label="게임 보드">`를 사용한다.
  - 점수 영역은 `<output>` 또는 `<span>`과 레이블로 구성한다.
  - 보드에 `role="application"`과 `aria-label="2048 게임 보드. 방향키로 타일을 이동합니다"`를 붙인다.
- **aria-live:**
  - 시각적으로 숨긴 `<p class="sr-only" aria-live="polite">` 하나를 둔다.
  - 이동 후 "점수 136점, 최고 타일 64" 같은 요약을 넣는다. 너무 잦은 안내를 피하려고 점수가 바뀐 경우에만 갱신한다.
  - 승리나 게임 오버는 `aria-live="assertive"` 영역에 알린다.
- **포커스:** 버튼과 보드에 `:focus-visible` 스타일을 적용한다(`outline: 2px solid var(--accent)`, `outline-offset: 2px`).
- **반응형 (모바일 우선):**
  - 컨테이너: `max-width: 480px`, 가운데 정렬, 좌우 패딩 `16px`
  - 보드 크기: `width: min(100%, 480px)`, `aspect-ratio: 1`. 375px 폭에서는 보드가 343px가 된다.
  - 칸 간격 `--gap: 8px`(모바일), `min-width: 480px`부터 `12px`
  - 타일 글자 크기는 보드 너비에 비례하게 정한다. 예: `font-size: calc(var(--cell) * 0.45)`. 세 자리는 0.38배, 네 자리 이상은 0.3배로 줄인다.
  - 어떤 폭에서도 가로 스크롤이 생기지 않아야 한다(`overflow-x` 금지, 고정 px 폭 금지).
  - 터치 대상(새 게임, 계속하기, 다시 하기 버튼)은 최소 `44px × 44px`이다.
  - iframe 높이가 낮을 수 있으므로 `body`에 `min-height: 100vh`를 강제하지 않는다. 내용 높이만큼만 차지하게 한다.

## 6. 테마/디자인

### 6.1 테마 결정 (블로그와 동일)
- `<head>`에 인라인 스크립트를 넣는다. 블로그 `index.html`과 같은 로직이다.
  - 결정 순서: `localStorage.getItem('theme')`(`'light'|'dark'`) → `prefers-color-scheme`
  - 결정한 값을 `document.documentElement.dataset.theme`에 넣는다.
  - 렌더링 전에 실행해 깜빡임(FOUC)을 막는다.
- iframe으로 임베드되면 블로그와 같은 출처이므로 `theme` 키를 공유한다. `main.js`에서 다음 두 이벤트를 받아 `data-theme`을 즉시 갱신한다.
  - `storage` 이벤트: 부모 페이지가 토글하면 반영한다.
  - `matchMedia('(prefers-color-scheme: dark)')`의 `change` 이벤트: 저장값이 없을 때만 반영한다.
- 게임 페이지에는 별도의 테마 토글을 두지 않는다. 단독으로 열었을 때도 블로그 설정과 시스템 설정을 따른다.
- `font-family`는 블로그의 `--font-sans`와 같은 스택을 쓴다. 타일 숫자는 `font-variant-numeric: tabular-nums`, `font-weight: 700`으로 표시한다.

### 6.2 CSS 변수
블로그 기본 변수인 `--bg`, `--surface`, `--text`, `--muted`, `--accent`, `--accent-soft`, `--border`, `--font-sans`를 블로그와 같은 값으로 정의한다. 게임 전용 변수는 아래와 같다.

| 변수 | 라이트 | 다크 |
|---|---|---|
| `--board-bg` | `#d8dee4` | `#161b22` |
| `--cell-bg` | `#eef1f4` | `#21262d` |
| `--overlay-bg` | `rgba(255,255,255,0.85)` | `rgba(13,17,23,0.85)` |

### 6.3 타일 색상
- 강조색(파랑) 계열을 단계적으로 진하게 쓰고, 512 이상은 보라 계열로 바꾼다.
- 2048은 축하 색(호박색)으로 표시하고, 4096 이상은 `super` 색으로 표시한다.
- 아래 글자색과 배경 대비는 모두 4.5:1 이상을 목표로 한다. 타일 숫자는 큰 굵은 글씨라 최소 3:1이면 AA를 충족한다.
- 클래스 `tile-2` … `tile-2048`, `tile-super`에서 `--tile-bg`와 `--tile-fg`를 참조한다.

| 값 | 라이트 배경 / 글자 | 다크 배경 / 글자 |
|---|---|---|
| 2 | `#eef2ff` / `#1f2328` | `#1c2a44` / `#e6edf3` |
| 4 | `#dbe4ff` / `#1f2328` | `#1e3a6e` / `#e6edf3` |
| 8 | `#bfd0ff` / `#1f2328` | `#1d4ed8` / `#ffffff` |
| 16 | `#93b4fd` / `#1f2328` | `#2563eb` / `#ffffff` |
| 32 | `#6090f5` / `#1f2328` | `#3b82f6` / `#0d1117` |
| 64 | `#2563eb` / `#ffffff` | `#60a5fa` / `#0d1117` |
| 128 | `#1d4ed8` / `#ffffff` | `#93c5fd` / `#0d1117` |
| 256 | `#1e40af` / `#ffffff` | `#bfdbfe` / `#0d1117` |
| 512 | `#7c3aed` / `#ffffff` | `#a78bfa` / `#0d1117` |
| 1024 | `#6d28d9` / `#ffffff` | `#c4b5fd` / `#0d1117` |
| 2048 | `#b45309` / `#ffffff` | `#fbbf24` / `#0d1117` |
| super | `#1f2328` / `#ffffff` | `#e6edf3` / `#0d1117` |

- 타일 모서리는 `border-radius: 6px`로 둥글게 한다. 그림자와 그라디언트는 쓰지 않고 장식을 최소화한다.
- 점수 상자는 `--surface` 배경, `--border` 테두리, 레이블은 `--muted`로 표시한다.
- 새 게임 버튼은 `--accent` 배경에 흰색 글자다. 다크 모드에서는 `--accent`(`#60a5fa`) 배경에 `#0d1117` 글자로 대비를 확보한다.

- [ ] 점수가 병합된 값의 합만큼 늘어난다.
- [ ] 최고 점수가 새로고침 후에도 유지된다.
- [ ] 시크릿 모드나 저장소 차단 환경에서도 오류 없이 플레이할 수 있다.

**조작**
- [ ] 방향키와 WASD가 동작하고, 게임 키를 처리할 때 페이지가 스크롤되지 않는다.
- [ ] 버튼에 포커스가 있을 때 Enter/Space가 정상 동작한다.
- [ ] 모바일(375px)에서 보드 위 스와이프로 네 방향 모두 조작할 수 있다.
- [ ] 보드 위 스와이프가 페이지를 스크롤하지 않고, 보드 밖에서는 스크롤이 정상이다.

**화면·테마**
- [ ] 375px 폭에서 가로 스크롤이 없다(`document.documentElement.scrollWidth <= innerWidth`).
- [ ] 버튼이 44px 이상이다.
- [ ] 라이트/다크 모두 모든 타일 숫자가 읽힌다(6.3의 대비 기준).
- [ ] 블로그에서 테마를 바꾸면 게임에도 반영된다. 새로고침과 iframe의 `storage` 이벤트 모두 확인한다.
- [ ] 테마 깜빡임이 없다.
- [ ] 하드코딩된 색상 없이 CSS 변수만 사용한다. 타일 단계 정의는 예외다.
- [ ] `prefers-reduced-motion`에서 애니메이션이 꺼진다.

**접근성·코드**
- [ ] 키보드만으로 새 게임, 플레이, 오버레이 버튼을 모두 조작할 수 있다. 포커스 표시가 보인다.
- [ ] 점수 변화와 승리·게임 오버가 aria-live로 안내된다.
- [ ] 콘솔 오류가 없다. ES 모듈을 쓰고 전역 변수와 `var`가 없다. 주석과 UI 문구는 한국어다.
- [ ] `apps/2048/` 밖의 파일을 수정하거나 참조하지 않는다.
- [ ] `node serve.js` 후 `http://localhost:8000/apps/2048/`에서 동작한다.
