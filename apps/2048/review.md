# 2048 Review 결과

## 1. 요약
**통과(수정 1건 반영).** spec.md 7장 완료 기준을 대부분 브라우저와 Node로 확인했다. 승리와 게임 오버가 같은 이동에서 동시에 일어나면 게임 오버 오버레이가 영영 뜨지 않는 버그를 찾아 `js/main.js`에서 고쳤다.

## 2. 검증 환경
- **브라우저:** 내장 브라우저(`mcp__Claude_Browser__*`)를 사용했다. `preview_start {name:"blog"}`로 `node serve.js 8000`을 띄우고 `http://localhost:8000/apps/2048/`에서 확인했다.
  - 키 입력: 실제 키 입력(`computer` key)과 `KeyboardEvent` 디스패치를 함께 썼다.
  - 승리/게임 오버: `localStorage['2048-state']`에 보드를 넣고 새로고침해 재현했다.
  - 스와이프: `pointerType:'touch'`인 `PointerEvent`를 합성해 확인했다.
  - 테마: `resize_window`의 `colorScheme`(light/dark)와 mobile 프리셋(375×812)을 썼다. 검증 후 desktop으로 되돌렸다.
- **참고:** 브라우저 패널이 백그라운드 상태(`visibilityState: hidden`)여서 타이머가 지연되고, 새로고침 직후 첫 클릭과 키 입력이 가끔 전달되지 않았다. 앱 문제가 아니라 도구 환경 문제로 판단했다. 이 경우 다시 시도하거나 이벤트를 디스패치해 확인했다.
- **Node(로컬):** `game.js`를 임시 스크립트(OS 임시 폴더, 검증 후 삭제)로 import해 로직을 검증했다. `storage.js`는 `localStorage`가 예외를 던지는 가짜 객체를 넣어 확인했다.
- **코드 리뷰:** `index.html`, `style.css`, `js/*.js` 전체를 읽었다.

## 4. 발견한 문제와 수정 내역
- **`js/main.js` — 승리와 게임 오버가 동시에 일어날 때 게임 오버 미표시 (수정함)**
  - 원인: 마지막 빈칸을 채우는 이동에서 2048이 만들어지고 보드가 꽉 차면 `justWon`이 우선해 승리 오버레이만 뜬다. [계속하기]를 누른 뒤에는 어떤 이동도 `moved:false`가 되어 게임 오버 판정이 다시 실행되지 않으므로 게임이 멈춘다.
  - 재현: `[[1024,1024,4,8],[4,8,16,32],[8,16,32,64],[16,32,64,128]]`에서 왼쪽 이동 → `justWon:true, over:true`.
  - 수정: [계속하기] 핸들러에서 `state.over`이면 바로 `renderer.showOver(state.score)`를 호출한다.
  - 재확인: 같은 보드로 승리 오버레이 → 계속하기 → 게임 오버 오버레이 표시, [다시 하기] 포커스, assertive 안내 확인.

## 5. 보류 사항 / 확인하지 못한 것
- 실제 터치 기기에서 스와이프와 스크롤 방지는 확인하지 못했다. 합성 이벤트와 코드 리뷰로만 확인했다.
- `prefers-reduced-motion` 에뮬레이션을 할 수 없어 코드 리뷰로만 확인했다.
- 실제 iframe 임베드 상태에서 부모 페이지 토글 → `storage` 이벤트 수신은 직접 확인하지 못했다. 이벤트를 디스패치해 처리 로직만 확인했다.
- (경미, 보류) 오버레이가 열려 있어도 `N` 키를 누르면 새 게임이 시작된다. 명세는 "방향 입력"만 무시하라고 하므로 위반은 아니라고 판단했다.
- 검증하며 바꾼 `localStorage`의 `2048-state`, `2048-best`, `theme`는 검증 후 삭제했다.
