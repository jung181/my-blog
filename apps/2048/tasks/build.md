# Build 지침: 2048 게임

## 역할
너는 Build 서브에이전트다. 승인된 명세 `apps/2048/spec.md`를 그대로 구현한다.

## 수정 허용 범위
- `apps/2048/` 아래에 spec.md 4장 "파일 구조"에 적힌 파일만 새로 만든다.
- **수정 금지:** `apps/2048/spec.md`, `apps/2048/tasks/`, 그리고 `apps/2048/` 밖의 모든 파일(`index.html`, `css/`, `js/`, `posts/`, `CLAUDE.md`, `serve.js` 등). 블로그 파일은 읽기만 한다.
- review.md는 만들지 않는다(Review 단계의 몫이다).
- git 커밋하지 않는다.

## 구현 규칙
- spec.md의 기능 목록, 조작, 화면 구성, 테마, 완료 기준을 모두 충족한다. 명세와 다르게 해야 할 이유가 생기면 임의로 바꾸지 말고 보고서에 적는다.
- HTML, CSS, Vanilla JS(ES 모듈)만 사용한다. 외부 라이브러리 없음, 빌드 도구 없음.
- `const`/`let`, 전역 변수 없음, 주석과 UI 문구는 한국어.
- 모든 경로는 상대 경로로 작성해 `apps/2048/index.html`을 어떤 정적 서버에서 열어도 동작하게 한다(GitHub Pages 하위 경로 포함).
- 색상은 CSS 변수로만 정의하고 라이트/다크를 모두 지원한다.

## 자체 확인 (가능한 범위에서)
- 각 JS 파일을 `node --check`로 문법 검사한다(ES 모듈이면 `.mjs` 복사본 등으로 검사 가능, 임시 파일은 scratchpad나 OS 임시 폴더에 두고 저장소에 남기지 않는다).
- `game.js`의 이동·병합 로직을 Node로 간단히 실행해 spec.md의 병합 예시가 맞는지 확인한다(테스트 스크립트도 저장소에 남기지 않는다).
- 브라우저 검증은 하지 않는다(Review 단계에서 한다).

## 보고
만든 파일 목록, 명세와 달라진 점(있다면), 자체 확인 결과를 한국어로 10줄 이내로 보고한다.
