# Plan 지침: 2048 게임

## 역할
너는 Plan 서브에이전트다. 코드를 구현하지 말고 **계획 문서만** 작성한다.

## 사용자 요청
> 2048 게임을 만들어줘. 방향키로 숫자 타일을 밀어서 합치는 퍼즐 게임이야. 점수판도 넣어줘.

## 산출물
- `apps/2048/spec.md` 파일 하나만 새로 만든다. 다른 파일은 만들거나 수정하지 않는다.

## 반드시 지킬 제약 (프로젝트 규칙)
- HTML, CSS, JavaScript(Vanilla JS)만 사용한다. 프레임워크·빌드 도구 없음. 외부 라이브러리는 최소화(CDN은 허용하지만 이 게임에는 필요 없게 설계).
- 웹앱은 `apps/2048/` 폴더 안에서 자체 완결된다. 블로그의 다른 파일(`index.html`, `css/`, `js/`, `posts/`)에 의존하거나 수정하지 않는다.
- 모바일에서도 플레이 가능해야 한다: 방향키 외에 **스와이프(터치) 조작**, 375px 폭에서 가로 스크롤 없음, 터치 대상 최소 44px.
- 블로그와 시각적으로 어울리도록 블로그의 테마 규칙을 따른다. 참고: `css/style.css`의 `:root` / `[data-theme="dark"]` 변수, `index.html` `<head>`의 인라인 테마 결정 스크립트(`localStorage`의 `theme` 키 → `prefers-color-scheme`). 색상은 CSS 변수로만 정의하고 라이트/다크 모두 지원한다. 블로그 메인에서 iframe으로 임베드될 수 있다는 점을 고려한다.
- ES 모듈, `const`/`let`, 전역 변수 없음. 주석과 UI 문구는 한국어.
- 접근성: 시맨틱 태그, `aria-label`, 점수 변화·게임 종료 안내(`aria-live`), 키보드 포커스 표시.

## spec.md에 담을 내용
1. 개요 — 무엇을 만드는지 한두 문장
2. 기능 목록 — 핵심 규칙(4×4 보드, 2/4 타일 생성 확률, 이동·병합 규칙, 한 번 이동에 타일당 1회 병합), 점수판(현재 점수 + 최고 점수 `localStorage` 저장, `try/catch`), 새 게임 버튼, 2048 달성(승리 후 계속하기) / 더 이상 이동 불가(게임 오버) 처리, 타일 이동·생성·병합 애니메이션 수준
3. 조작 — 키보드(방향키, 필요 시 WASD), 스와이프, 스크롤 방지 범위
4. 파일 구조 — `apps/2048/` 아래 파일과 각 역할 (게임 로직과 렌더링 분리 권장)
5. 화면 구성 — 레이아웃 스케치(텍스트), 반응형 기준
6. 테마/디자인 — 사용할 CSS 변수, 타일 색상 단계(라이트·다크 모두 대비 확보)
7. 완료 기준(테스트 체크리스트) — Review 단계에서 확인할 항목
8. 범위 밖 — 이번에 하지 않을 것 (예: 되돌리기, 보드 크기 변경 등)

간결하게, 구현자가 그대로 따라 만들 수 있을 정도로 구체적으로 쓴다. 작성 후 spec.md의 요약을 5줄 이내로 보고한다.
