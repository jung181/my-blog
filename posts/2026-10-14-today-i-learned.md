오늘은 클로드 코드와 함께 이 블로그를 처음부터 만들어 봤어요. 프레임워크 없이 HTML, CSS, JavaScript만 썼더니 셋이 각각 무슨 일을 하는지 분명하게 보였습니다.

한 줄로 요약하면 이렇습니다.

> HTML은 **뼈대**, CSS는 **옷**, JavaScript는 **움직임**이다.

## HTML: 내용과 구조

HTML은 페이지에 **무엇이 있는지**를 정합니다. 제목, 문단, 링크, 버튼 같은 내용과 그 구조를 표시해요.

- `<header>`, `<main>`, `<footer>`처럼 의미가 담긴 태그를 쓰면 구조를 이해하기 쉽고, 화면 낭독기 같은 보조 기기도 페이지를 더 잘 읽어요.
- 이 블로그의 `index.html`은 뼈대만 담고 있어요. 머리말, 글이 들어갈 빈 자리(`<main id="app">`), 꼬리말이 전부입니다.
- `<meta name="viewport">` 한 줄이 있어야 휴대폰에서 화면이 제 크기로 보인다는 것도 배웠어요.

```html
<header>나의 블로그</header>
<main id="app"></main>
<footer>© 2026</footer>
```

## CSS: 모양과 배치

CSS는 내용이 **어떻게 보일지**를 정합니다. 글꼴, 색, 여백, 배치를 담당해요.

- **CSS 변수**로 색을 한곳에 모아 두면 다크 모드가 쉬워져요. 테마가 바뀔 때 변수 값만 바꾸면 페이지 전체 색이 함께 바뀝니다.
- **미디어 쿼리**로 화면 폭에 따라 다른 스타일을 줄 수 있어요. 작은 화면 기준으로 먼저 만들고, 넓은 화면에서 글자를 키우는 식으로 모바일에 대응했어요.
- `word-break: keep-all`을 쓰면 한글 단어가 중간에서 끊기지 않아 읽기 편해져요.

```css
:root { --bg: #ffffff; --text: #1f2328; }
[data-theme="dark"] { --bg: #0d1117; --text: #e6edf3; }

body {
  background-color: var(--bg);
  color: var(--text);
}
```

## JavaScript: 동작과 변화

JavaScript는 페이지가 **어떻게 반응할지**를 정합니다. 데이터를 불러오고, 화면을 바꾸고, 사용자의 클릭에 응답해요.

- `fetch()`로 `posts` 폴더의 마크다운 파일을 불러와요.
- 직접 만든 변환기가 마크다운을 HTML로 바꿔서 화면에 넣어요.
- 주소의 `#` 뒤 경로를 보고 글 목록을 보여줄지, 글 본문을 보여줄지 정해요.
- 다크 모드 버튼을 누르면 테마를 바꾸고, 선택을 브라우저에 저장해 다음에도 유지해요.

```js
button.addEventListener('click', () => {
  const next = root.dataset.theme === 'dark' ? 'light' : 'dark';
  root.dataset.theme = next;
});
```

## 세 가지가 함께 일하는 방식

| 역할 | 담당 | 이 블로그에서 하는 일 |
|:---|:---|:---|
| 구조 | HTML | 머리말, 본문 자리, 꼬리말 |
| 모양 | CSS | 글꼴, 색, 다크 모드, 모바일 화면 |
| 동작 | JavaScript | 글 불러오기, 마크다운 변환, 화면 전환 |

셋을 파일별로 나눠 두니 고칠 곳을 찾기도 쉬웠어요. 색을 바꾸고 싶으면 CSS만, 기능을 고치고 싶으면 JavaScript만 보면 되니까요.

## 그 밖에 알게 된 것

- 브라우저에서 파일을 직접 열면(`file://`) 보안 정책 때문에 `fetch()`가 막혀요. 그래서 로컬 서버를 띄워서 확인해야 했어요.
- 사용자가 쓴 글을 화면에 넣을 때는 HTML 특수문자를 먼저 바꿔 줘야 해요(이스케이프). 그래야 글 속의 `<script>` 같은 코드가 실행되지 않아요.
